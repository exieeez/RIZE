### Б6. `AudioEffectsManager.kt` — публичное API и вызовы

Публичное API (`:33–58`): `attachPlayer(ExoPlayer)`, `onAudioSessionIdChanged(Int)`, `detachPlayer()`, `setReverb(String)`, `setBassBoost(Boolean)`; наружу — `StateFlow` `reverbPreset` (`:27–28`) и `bassBoostEnabled` (`:30–31`).

Умеет ровно два эффекта:
- **PresetReverb** (`:69–89`): `PresetReverb(0, 0)` + маппинг `hall→PRESET_LARGEHALL`, `room→PRESET_LARGEROOM`, `plate→PRESET_PLATE`, остальное `PRESET_MEDIUMHALL`; подключается как aux-эффект: `p.setAuxEffectInfo(AuxEffectInfo(reverb.id, 1.0f))` (`:84`).

Кто вызывает: `PlaybackService.onCreate` (`:69–70` attach; `:66–68` смена сессии); `PlayerController.setReverb/setBassBoost` (`:362–371`) ← `VotifyRoot.kt:379–380` (ре-применение при смене трека: `LaunchedEffect` с ключами `cp.reverbPreset, cp.bassBoost, playerState.current?.id`, строки 367–375) и ← живой ремикс-шит `onSetRemix` (`VotifyRoot.kt:862–864`). ### Б8. Кроссфейд — отсутствует. Однозначно.

Все совпадения `crossfade` в Kotlin-коде Android:
- `CustomPrefs.kt:27` — поле;
- `AudioSettingsScreen.kt:68–71` — тумблер;
- `VotifyApp.kt:55` и `BackgroundsScreen.kt:277` — **Coil `.crossfade(true)`**: кроссфейд картинок в UI, к звуку отношения не имеет;
- `PlayerScreen.kt:984` — комментарий о плавной смене палитры обложки (визуал).

`rg -i "volume|fade"`: ни одного `setVolume`, ни одного `Animatable` на громкость, ни `setPauseAtEndOfMediaItems`, ни двух плееров. Всё «fade» — Compose `fadeIn/fadeOut` для анимаций интерфейса (`VotifyRoot.kt:750,813–814`, `PlayerScreen.kt:307` и др.).

При этом **на PC (Electron) кроссфейд реализован полностью** — это эталон «того же кроссфейда»: `src/main.js:7197–7382` — слайдер секунд (`:7199–7208`), предзагрузка следующего трека во второй `<audio>` (`preloadNextTrackForSeamless`, `:7233–7257`), тик-хендлер: при `remaining <= cf` → `startSeamlessCrossfade` (`:7277–7280`), при `cf===0 && gapless` — мгновенная передача (`:7280–7282`), сам кроссфейд: `inactivePlayer.volume = 0` + interval-сведение громкостей (`:7286–7318`).

### Б9. Переход к следующему треку

- Очередь: `setMediaItems(...)` + `prepare()` + `play()` (`PlayerController.kt:162–164`, при реконнекте `:167–169`).
- Ручной next: `seekToNextMediaItem()` (`:211–212`), previous — рестарт после 3 с либо `seekToPreviousMediaItem()` (`:215–218`), переход по элементу очереди `:289–296`.
- Автопереход в конце трека выполняет сам ExoPlayer (плейлист из MediaItem'ов): код **не переопределяет** `onMediaItemTransition`; переход наблюдается только через `onEvents` c `EVENT_MEDIA_ITEM_TRANSITION` для записи истории и виджета (`PlayerController.kt:88–93`).

## В. Итог

### В10. Что мёртвое, что работает

**Мёртвое (сохраняется, ни на что не влияет) — 9 штук:** `caching`, `gapless`, `crossfade`, `normalization`, `onNotification`, `autoplay`, `similarToQueue`, `restoreQueue` (все — только экран: `AudioSettingsScreen.kt:56–118`), плюс `volumeButtonsSkip` (`SettingsRepository.kt:85`, читателей логики нет). Это те контролы, которые надо «оживлять».

**Работает полностью:** качество потока (server POST + embedded `resolveAudioUrl(trackId, quality)`), `playbackSpeed`, `playbackPitch`, `pitchShiftLinked`, `reverbPreset` (PresetReverb→aux), `bassBoost` (BassBoost по сессии).

**Частично:** нет ни одного частично работающего аудио-контрола; `gapless` де-факто обеспечивается дефолтным автопереходом ExoPlayer внутри плейлиста, но тумблер с этим поведением не связан (выключить/включить им нельзя).

### Возможен ли кроссфейд на текущем стеке

**Встроенного кроссфейда в Media3 нет** — подтверждено первоисточниками: тикет androidx/media#2 «Feature request (fade and crossfade audio)» **открыт** с 2021-го, цитата: *«Since current implementation of media3 supports only one Exoplayer, hence crossFade seems not possible»* (https://github.com/androidx/media/issues/2, прочитан целиком); более старый google/ExoPlayer#3438 закрыт как duplicate (https://github.com/google/ExoPlayer/issues/3438, прочитан целиком).

Техническая возможность на текущем коде — **есть**, двумя путями (факты по инфраструктуре, без патча):
1. **Два плеера (настоящий кроссфейд, как на PC).** ExoPlayer — обычный объект; в `PlaybackService` можно держать второй экземпляр со своим `player.setVolume(...)`. Ограничения, вытекающие из текущего кода: MediaSession/уведомление/виджет привязаны к одному плееру (`session.player`, `PlaybackService.kt:83–86`), аудиофокус включён на первом (`handleAudioFocus=true`, `:57–61`), эффекты `AudioEffectsManager` висят на сессии первого плеера (`:69–70`) — второй плеер будет без reverb/bass, если их к нему не подключить отдельно. Роль тикера для старта фейда уже играет существующий `ticker` (500 мс), но он живёт в UI-слое `PlayerController`, а плеер — в сервисе: логику кроссфейда место — сервис. Преф `crossfade` — Boolean; для секунд (как PC 0–12 с) в `CustomPrefs` поля длительности нет (`CustomPrefs.kt:25–37`).
2. **Один плеер (фейд без перекрытия).** Через существующий `ticker`/позицию плавно гасить `setVolume` у текущего элемента перед концом и переключать `seekToNextMediaItem` — затухание будет, перекрытия двух треков (определение кроссфейда) — нет; двух одновременных AudioTrack Media3 на одном ExoPlayer не создаёт.

**Ключевой вывод:** пользовательская претензия обоснована — 9 из 11 контролов экрана «Аудио» не подключены к плееру; реально действуют только качество и ремикс (скорость/pitch/reverb/bass), унаследованный от PC кроссфейд на Android отсутствует полностью, хотя поле-тумблер и вся строка настроек уже существуют.

**Граница соблюдена:** файлы не редактировались; патчи не предлагаются.
