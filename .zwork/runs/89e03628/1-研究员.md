# Вердикт по haze 0.7.3: карточка как hazeChild источника

## Сводка (уверенность: высокая по механике 0.7.3; «не подтверждено» по двум пунктам — отмечены)

1. В 0.7.3 **нет никакого поиска по дереву**. `hazeChild` только регистрирует `HazeArea` (координаты+размер) в общем объекте `HazeState`; размытие рисует узел `haze` — и рисует он **содержимое своего собственного поддерева**.
2. «Сиблинг» — **не архитектурное требование**, а следствие двух вещей: (а) пиксели для размытия должны лежать в поддереве источника; (б) патч размытия рисуется в слое источника, поэтому child должен отрисовываться позже него. Настоящий запрет — **child не должен быть потомком источника** (иначе он «размывает сам себя»).
3. Произвольное число `hazeChild` на один `HazeState` — поддерживается (документация 0.7.3 прямо это говорит).
4. Для карточки **внутри** `NavHost` (а `NavHost` лежит внутри источника `Box(431)`) настоящего «морозного стекла» в 0.7.3 не получится: карточка — **потомок** источника, и её собственные пиксели попадают в запись источника → она «заблюрится сама», а не фон.
5. **Ключевой ответ:** если источник = только слой обоев (отдельный узел, не содержащий `NavHost`), а карточка внутри `NavHost` — hazeChild на этот же state, то карточка **сработает** и размоет обои под собой. НО: в 0.7.3 такой источник неизбежно оказывается **вложен** в источник `Box(431)` для NavBar — а вложенные источники в свежих версиях крашились (issue #443, 1.1.1); для 0.7.3 это **не подтверждено**, нужен тест на устройстве.
6. Апгрейд: несколько источников + zIndex появились в **1.2.0** (PR #441); вложенные иерархии починены в **1.5.0** (#545). Версии haze ≥1.2.0 требуют Compose UI ≥1.7.6, то есть **без смены BOM не обойтись** (минимум BOM 2024.12.01).

## 1. Как HazeChildNode находит источник

Никак — он его не ищет. Связь только через общий объект `HazeState`.

`HazeChild.kt` @0.7.3 (commonMain), строки 122–130:
```kotlin
private fun attachToHazeState() {
  state.registerArea(area)
  attachedState = state
  ...
}
```
`Haze.kt` @0.7.3, строки 30–45:
```kotlin
class HazeState {
  private val _areas = mutableStateListOf<HazeArea>()
  val areas: List<HazeArea> get() = _areas.toList()
  fun registerArea(area: HazeArea) { _areas.add(area) }
  fun unregisterArea(area: HazeArea) { _areas.remove(area) }
}
```
Поиск родителя/предка/сиблинга: `grep -rn -iE "sibling|ancestor|parentNode|children"` по всем исходникам 0.7.3 — **пусто**. `HazeChildNode` — это `Modifier.Node` с `LayoutAwareModifierNode`/`GlobalPositionAwareModifierNode`, который лишь сообщает координаты (`onPlaced`, строки 108–112) и регистрирует область. **Связь = общий HazeState + экранные координаты; иерархия не участвует.**

Источник, в свою очередь, читает все области из state без фильтров (`AndroidHazeNode.kt` @0.7.3, строки 340–349):
```kotlin
effects = state.areas.asSequence()
  .filter { it.isValid }
  .map { area -> currentEffects.remove(area) ?: Effect(...) }
  .toList()
```
Никакой проверки «является ли область потомком/сиблингом» в 0.7.3 нет.

## 2. Жёстко ли требование «сиблинги»?

Нет. Никакого проверочного кода нет — требование вытекает из механики рисования (`AndroidHazeNode.kt` @0.7.3):

- Строки 273–280: весь контент поддерева источника записывается в `contentNode`:
  ```kotlin
  contentNode.record { canvas ->
    val scope = this@draw
    draw(scope, layoutDirection, Canvas(canvas), size) { scope.drawContent() }
  }
  ```
- Строки 289–299: запись выводится на экран с **вырезанными** зонами областей (`ClipOp.Difference`);
- Строки 302–326: в каждую зону рисуется **размытая копия** всей записи (`effect.renderNode` с `RenderEffect.createBlurEffect`, стр. 425–432) поверх.

Отсюда два реальных правила:
1. **Если child — потомок источника**: его пиксели входят в запись → в зоне child вырезается его же прямое рисование и подставляется размытая копия *включая саму карточку* → карточка размывается сама (артефакт, не краш — в 0.7.3 проверок типа 1.2.0-шной `require` нет).
2. **Если child в другой ветке** (не потомок источника): в записи источника его нет, патч = размытие того, что источник содержит в этих координатах; child рисуется позже, обычным порядком, и просвечивает сквозь патч. **Сработает.**

То есть ответ на прямо заданный подвопрос: **да, hazeChild вне поддерева источника (в другой ветке) работает** — это не сиблинг-требование, а лишь «не быть потомком + рисоваться после». Дополнительное подтверждение из официальных доков 1.3.0 (`docs/usage.md` @тег 1.3.0, раздел «Deep UI hierarchies») — там hazeEffect стоит на `Text` глубоко в поддереве `Foreground`, а источник — `Background` (соседняя ветка), state передаётся через CompositionLocal. Прямой аналог вашей ситуации, и он документирован как штатный.

## 3. Два hazeChild на один HazeState

**Да, поддерживается.** `docs/usage.md` @0.7.3, строки 73–74 (tip «Multiple hazeChilds»):
> "Note: We are using multiple `hazeChild`s in this example. You can actually use an abitrary number of `hazeChild`s."

Механика: каждая область получает собственный `Effect` со своим RenderNode (см. код из п.1, строки 340–349), все они рисуются источником в зоне своих областей. Неперекрывающиеся зоны (NavBar внизу, карточка в середине) друг другу не мешают. Нюансы 0.7.3: (а) патч получает **каждая** валидная область на этом state, фильтров нет; (б) при перекрытии патчи накладываются в порядке регистрации; (в) если на один state подвесить **два источника**, каждый нарисует свой патч для каждой области (двойное размытие) — «правильные» несколько источников появились только в 1.2.0. Поэтому для «двух слоёв» в 0.7.3 нужны **два отдельных HazeState**.

## 5. ПРЯМОЙ ОТВЕТ: источник = только обои, карточки внутри NavHost

**Да, сработает — карточка размоет обои под собой**, т.к. карточка не является потомком узла-обоев (узел-обои — её двоюродный сосед по ветке), а связь идёт только через общий `HazeState` + координаты. Патч рисуется в слое обоев (в `Box(431)` до `NavHost`), карточка отрисовывается после и просвечивает сквозь него, если её собственный фон полупрозрачный и промежуточные слои в её зоне не непрозрачны.

**Условия, при которых это верно** (все проверяемы по исходникам 0.7.3, п.1–2):
- карточка **не** потомок источника — её пиксели не попадают в запись источника;
- источник отрисовывается **раньше** карточки по порядку отрисовки (обои — раньше NavHost: да);
- в зоне карточки между слоем обоев и карточкой нет непрозрачных слоёв.

**Но — это моя аналитическая оценка по коду, а не протестированный факт.** Не подтверждено два момента: (а) поведение «вложенного источника» (обои-источник внутри Box431-источника) именно на 0.7.3 — риск краша по аналогии с #443; (б) реальная видимость патча при текущей структуре фонов (`base` + обои + `dim`). Рекомендуемый способ проверки: временный одноразовый тест на устройстве API 31+ (например, положить `Box{ background(обои).haze(state2) }` вторым ребёнком Box431 и повесить `hazeChild(state2)` на одну карточку), смотреть, размывается ли фон.

**Также важно:** если оставить карточку потомком `Box(431)` и повесить hazeChild на state1 — она **не сработает как стекло**: будет показана размытая копия её же пикселей (прямая цитата механики — «the content under each effect area is nicht drawn directly, instead the blurred copy is drawn», строки 289–299+302–326). Не краш, но визуальный артефакт.

## 6. На какую версию переходить

Появившееся в **1.2.0** (2025-01-09; PR #441, merged 2024-12-18) — цитата из CHANGELOG:
> "Add support for multiple Haze nodes attached to a HazeState in #441"
> "Haze now supports different `hazeEffect` areas which overlap..."
> в PR #441: "This means that there can be N haze nodes, and M hazeChild nodes attached to a state."

Переименования там же: `haze` → `hazeSource`, `hazeChild` → `hazeEffect` (старые имена сохранены deprecated — миграция пошаговая). Модель zIndex (docs @1.2.0, «Overlapping blurred layouts»): "By default, `hazeEffect` will draw all layers with a `zIndex` less than the value of the sibling `Modifier.hazeSource`"; есть `canDrawArea` для фильтра. Ключевой запрет, который снимает вашу проблему не полностью, а правильно: `require(!area.contentDrawing)` с текстом "Modifier.haze nodes can not draw Modifier.hazeChild nodes... use `canDrawArea` to filter out parent areas" — то есть **effect не может находиться внутри своего источника** и в 1.x. Рецепт для вашей задачи в 1.2.0+ — не «источник-обёртка + карточка-потомок», а «обои + элементы контента как sources (zIndex), карточка как effect» (так решаются sticky headers, recipes.md @1.2.0: элементы списка — `hazeSource`, header — `hazeEffect`). Вложенные иерархии доведены до ума в **1.5.0** (#545, «Fix support for nested Haze hierarchies»).
