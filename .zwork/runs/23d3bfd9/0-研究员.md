## Q3. Может ли узел-эффект быть ПОТОМКОМ узла-источника?

**Нет. В 0.7.x `haze` и `hazeChild` обязаны быть сиблингами (или, как минимум, не предком/потомком друг друга); если `hazeChild` — потомок `haze`, ребёнок будет размыт, а не «подложка».**

Подтверждение — прямое утверждение автора библиотеки (Chris Banes), issue #78 «Blur happens also in children», комментарий 2024-01-04:
> «No, the `haze` and `hazeChild` need to be siblings and not descendants of each other, otherwise the child will be blurred, as you've found.»
> …
> «Simple answer, no. It's just the way that Haze needs to work. We're basically doing our own (very limited) window layering, and I don't plan on doing anything more complex.»
Issue закрыт 2024-01-05 как working-as-intended; репортер отдельно просил поддержать вложенность — отказ.

Механическая причина видна в исходниках 0.7.3 (`AndroidHazeNode.kt`, `RenderNodeImpl.draw()`): узел-источник сначала рисует **свой собственный `drawContent()`** в `contentNode`, затем вырезает области `hazeChild` из этого `contentNode` способом `ClipOp.Difference` (комментарий в коде: *«otherwise you see the content behind blurred areas»*) и только после этого рисует размытые `RenderNode` поверх. То есть источник размывает ровно тот контент, который сам отрисовал. Если `hazeChild` лежит **внутри** этого контента, он попадает в `contentNode` и вырезается/размывается вместе с ним — что и описал автор.

Свежий апстрим это подтверждает косвенно: поддержка вложенных сценариев появилась позже — «Fix support for nested Haze hierarchies in #545» в **1.5.0** (2025-03-06), а «Add support for multiple Haze nodes attached to a HazeState in #441» — в 1.2.0. Ни того, ни другого в 0.7.3 нет.

**Уверенность: высокая** (прямое утверждение мейнтейнера + согласующаяся механика в коде именно 0.7.3). Оговорка: формулировка автора относится к 0.6.x/0.7.x-эпохе (issue от января 2024, до 0.7.0), и в 0.7.3 ничего в этом отношении не менялось (см. changelog 0.7.0–0.7.3 — там только «Integrate GlobalPositionAwareModifierNode», «Add ListOverImage sample», багфиксы, ничего про вложенность).

## Q4. Несколько источников на одном `HazeState` в 0.7.3

**Нет — в 0.7.3 на одном `HazeState` поддерживается один узел-источник (`haze`). Несколько `hazeChild` на одном стейте поддержаны (произвольное число), но несколько `haze` — нет.** Суммирования нескольких источников в один backdrop в 0.7.3 нет.

Механика из `AndroidHazeNode.kt` 0.7.3: `HazeNode` регистрирует **свои** `position`/`size` и в `Impl.update(...)` размывает собственный `drawContent()`; `HazeState` хранит только список **areas** (от `hazeChild`):
```kotlin
@Stable
class HazeState {
  private val _areas = mutableStateListOf()   // только области hazeChild
  val areas: List get() = _areas.toList()
  fun registerArea(area: HazeArea) { _areas.add(area) }
  fun unregisterArea(area: HazeArea) { _areas.remove(area) }
}
```
В `HazeState` нет ни реестра источников, ни z-порядка — сравни с 1.2.0, где `HazeArea` получил `var zIndex: Float by mutableFloatStateOf(0f)` и понадобился PR #441 «Add support for multiple Haze nodes attached to a `HazeState`»: *«This means that there can be N haze nodes, and M hazeChild nodes attached to a state.»* Именно этой возможности в 0.7.3 ещё нет.

Подтверждение «одна areas-коллекция, много детей» — docs 0.7.3 (`docs/usage.md`, секция Scaffold):
> «!!! tip "Multiple hazeChilds" — Note: We are using multiple `hazeChild`s in this example. You can actually use an abitrary number of `hazeChild`s.»

Практический вывод для сценария из вопроса (фоновая картинка на одном узле + контент NavHost на другом): **в 0.7.3 так сделать нельзя** — только один источник. Нужно либо поднять `haze` на общий родительский узел, включающий и картинку, и контент, либо обновить библиотеку.

**Уверенность: высокая** по «нельзя несколько источников» (отсутствие zIndex/реестра источников в ABI + PR #441 как явное добавление этой возможности в 1.2.0). Цитата «N haze nodes… in a state» — из PR 1.2.0, это первичный источник о том, что ранее такой поддержки не было.

## Q5. Как задать «iOS-подобную» полупрозрачную подложку в 0.7.3

Три параметра, все в `HazeStyle`:

**(а) Сила размытия — `blurRadius: Dp`.** В `HazeStyle`/`HazeDefaults`. Дефолт `HazeDefaults.blurRadius = 20.dp`. В `RenderNodeImpl` уходит в `RenderEffect.createBlurEffect(blurRadiusPx, blurRadiusPx, Shader.TileMode.CLAMP)`, где `blurRadiusPx = with(density) { resolvedStyle.blurRadius.toPx() }`.

**(б) Цвет/альфа тона — `tint: Color`.** Это **обычный `Color` с альфой** — именно так задаётся полупрозрачный тон поверх размытого фона. Ключевое (из kdoc 0.7.3):
```kotlin
/**
 * @property tint Default color to tint the blurred content.
 * Should be translucent, otherwise you will not see the blurred content.
 */
```
То есть чтобы получить «полупрозрачный тон поверх размытого», нужно `tint = baseColor.copy(alpha = <0..1>)` — ровно то, что уже делает ваш код на строке 958. В `docs/usage.md` 0.7.3: *«A tint effect is applied, primarily to maintain contrast and legibility. By default we use the provided background color at 70% opacity.»* — `HazeDefaults.tintAlpha = 0.7f`.

Разрешение стилей (`resolveStyle` в 0.7.3) — стиль `hazeChild` переопределяет **только заданные** поля, остальные берутся из стиля `haze`-источника, с финальными фолбэками:
```kotlin
internal fun resolveStyle(default: HazeStyle, child: HazeStyle): HazeStyle = HazeStyle(
  tint = child.tint.takeOrElse { default.tint }.takeOrElse { Color.Transparent },
  blurRadius = child.blurRadius.takeOrElse { default.blurRadius }.takeOrElse { 0.dp },
  noiseFactor = child.noiseFactor.takeOrElse { default.noiseFactor }.takeOrElse { 0f },
)
```
Здесь `takeOrElse` для `tint`/`blurRadius` — это `androidx.compose.ui.graphics.isSpecified` / `Dp.isSpecified`. Отсюда важное следствие: **`Color.Unspecified` и `Dp.Unspecified` = «не задано, взять из другого уровня»**, а не «прозрачный»/«ноль». Если нужно именно «без тона», надо передавать `Color.Transparent` явно.

**(в) Fallback, когда размытие недоступно.** В 0.7.3 настраиваемого `fallbackTint` **нет** (в ABI 0.7.3 его нет; в changelog он появляется позже — `* Clarify fallbackTint kdoc in #647` в 1.6.1 и `* Implement fallback for HazeProgressive in #400`). Поведение жёстко зашито:
- Выбор реализации (`AndroidHazeNode.updateImplIfRequired`): `RenderNodeImpl` — только при `Build.VERSION.SDK_INT >= 32` (в коде явно: *«We can't currently use RenderNode impl on API 31 due to https://github.com/chrisbanes/haze/issues/77»*) и при аппаратно-ускоренном канвасе и не в preview; иначе — `ScrimImpl`.
- `ScrimImpl` (fallback) рисует не размытие, а **полупрозрачную заливку вашим же `tint`**, причём альфа искусственно усиливается:
```kotlin
private fun Color.boostAlphaForBlurRadius(blurRadius: Dp): Color {
  // We treat a blur radius of 72.dp as near 'opaque', and linearly boost using that
  val factor = 1 + (blurRadius.value / 72f)
  return copy(alpha = (alpha * factor).coerceAtMost(1f))
}
```
То есть на API < 32 (и в превью/Robolectric/software canvas) вы получите `tint` с усиленной альфой (`alpha * (1 + blurRadius/72)`, максимум 1.0) — при больших `blurRadius` тон становится почти непрозрачным. Учесть это при выборе `blurRadius` и альфы, если важна одинаковая картинка на старых устройствах.

**Уверенность: определённо** по всем трём пунктам (ABI + первоисточники 0.7.3 + docs 0.7.3).

- Вариант с deprecated-перегрузкой (если сознательно нужен старый стиль API): `Modifier.hazeChild(state = hazeState, shape = shape, tint = baseColor.copy(alpha = ...), blurRadius = effectiveBlurDp.dp)` — компилируется, но даст предупреждение `Deprecated: Replaced with new HazeStyle object`.
- Для «iOS-подобного» вида в целом ориентируйтесь на `HazeDefaults.style(backgroundColor = ...)`: он применяет `HazeDefaults.tint(color)` = `color` с альфой `alpha * 0.7f`, что и есть задокументированный дефолт «70% opacity».

**(3) Fallback (когда размытие недоступно) в 0.7.3 не настраивается кодом приложения.** Управлять можно только косвенно: через `tint` + `blurRadius` (fallback `ScrimImpl` рисует `tint` с усиленной альфой: `alpha * (1 + blurRadius.value/72f)`, ↑ до 1.0). Если нужен одинаковый вид на API < 32 — держите `alpha` низкой и/или `blurRadius` небольшим.
